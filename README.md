# ระบบเบิก-ยืมพัสดุ (Supply Withdraw & Borrow)

> **มี 2 แบบให้เลือก**
> 1. **ระบบเบิก-ยืมพัสดุ บน GitHub Pages (ฟรี)** อยู่ในโฟลเดอร์ `docs/` เก็บข้อมูลใน Google Sheets ไม่ต้องมีเซิร์ฟเวอร์ ← แนะนำ
> 2. **แบบเซิร์ฟเวอร์ (Node.js)** อยู่ในโฟลเดอร์ `src/`, `public/` ระบบยืม-คืนอุปกรณ์ที่มีผู้ใช้/รหัสผ่านรายคน (รายละเอียดด้านล่าง)

## ระบบเบิก-ยืมพัสดุ: GitHub Pages + Google Sheets

### ความสามารถ
- **เลือกได้ 2 แบบ**
  - **เบิกพัสดุ** — เวชภัณฑ์/วัสดุสิ้นเปลือง เบิกแล้วไม่ต้องคืน
  - **ยืมพัสดุ** — ครุภัณฑ์/อุปกรณ์ ต้องระบุ **วันคืน**
- กรอกแค่ **ชื่อ-นามสกุล**, **แผนก** (เลือกจากรายการในชีต) และ **วันคืน** (เฉพาะการยืม) แล้วเลือกพัสดุพร้อมจำนวน
- ส่งฟอร์มแล้ว **ตัดสต็อกใน Google Sheet ทันที** ไม่เกินยอดคงเหลือ
- ระบบสร้าง **ใบเบิก/ใบยืมเป็น PDF (A4)** อัตโนมัติ แล้วถามผู้กรอกว่า *"อนุญาตให้บันทึกไฟล์ลงในเครื่องนี้หรือไม่?"*
  - Chrome / Edge บนคอมพิวเตอร์: เปิดหน้าต่าง Save ของระบบให้เลือกที่เก็บไฟล์
  - Safari / iPhone / Android / Firefox: ดาวน์โหลดผ่านตัวจัดการดาวน์โหลดของเบราว์เซอร์
  - ในเอกสารมีช่องลงลายมือชื่อ **ผู้เบิก/ผู้ยืม** และ **เจ้าหน้าที่พัสดุ** (เจ้าหน้าที่ออกเอกสารซ้ำได้จากหน้า "ประวัติเบิก-ยืม")
- หน้าเลือกพัสดุ: ค้นหาแบบไม่สนช่องว่าง (เช่น `airway100`), แสดงเฉพาะที่มีของเป็นค่าเริ่มต้น, ดูเฉพาะที่เลือกไว้, กระโดดตามตัวอักษร A–Z / ก–ฮ
- หน้า **พัสดุคงเหลือ** แสดงยอดล่าสุดจากชีต
- **โหมดเจ้าหน้าที่ (PIN)** — **ประวัติเบิก-ยืม** (ค้นหา/ส่งออก CSV), **สรุปรายเดือน (PDF)**, รับคืนพัสดุ (คืนบางส่วน/แจ้งชำรุดได้), รับเข้า, ตรวจนับ, ตัดชำรุด, เพิ่ม/แก้พัสดุ, จัดการแผนก/หมวดหมู่, ภาพรวม และประวัติสต็อก
  - ประวัติเบิก-ยืม (ชื่อผู้ขอ ฯลฯ) ส่งจาก Apps Script **เฉพาะเมื่อมี PIN** ผู้ใช้ทั่วไปเห็นแค่สต็อก แผนก และใบที่ตัวเองเพิ่งส่ง
  - **สรุปรายเดือน (PDF)** ที่หน้า ภาพรวม หรือ ประวัติเบิก-ยืม: เลือกเดือน → ยอดรวม, พัสดุที่ถูกเบิก (เรียงตามจำนวน), พัสดุที่ถูกยืม/คืน/ค้างคืน, สรุปตามแผนก, รายการเอกสารทั้งหมด และช่องลงชื่อผู้จัดทำ/หัวหน้างานพัสดุ
- หน้าตาสไตล์ Apple รองรับมือถือ และโหมดมืด (Dark mode) ตามการตั้งค่าเครื่อง

### ขั้นที่ 1: เปิดเว็บบน GitHub Pages (ประมาณ 2 นาที)
1. เข้า repo บน GitHub แล้วไปที่ **Settings → Pages**
2. ที่ **Source** เลือก **Deploy from a branch**
3. ที่ **Branch** เลือก branch ที่มีโค้ดนี้ (หรือ `main` ถ้ารวมโค้ดเข้า main แล้ว) แล้วเลือกโฟลเดอร์ **`/docs`** จากนั้นกด **Save**
4. รอ 1–2 นาที แล้วเว็บจะอยู่ที่ **https://cocolnwza004.github.io/borrow/**

ตอนนี้เว็บใช้งานได้แล้วใน **โหมดทดลอง** ข้อมูลเก็บในเบราว์เซอร์แต่ละเครื่อง และ PIN เจ้าหน้าที่คือ `1234`

### ทางเลือก: เผยแพร่ด้วย Netlify (ฟรี) แทน GitHub Pages
repo มีไฟล์ [`netlify.toml`](netlify.toml) อยู่แล้ว (เผยแพร่โฟลเดอร์ `docs/` ไม่ต้อง build และใส่ส่วนหัวความปลอดภัยให้ เช่น CSP ที่อนุญาตเฉพาะสคริปต์ของเว็บเอง + Google Apps Script)
1. เข้า https://app.netlify.com → **Sign up / Log in with GitHub**
2. **Add new site → Import an existing project → GitHub** → อนุญาต Netlify (เลือก *Only select repositories* → `borrow` ได้)
3. เลือก repo `borrow` และ **Branch to deploy** = branch ที่มีโค้ดนี้
   ช่อง Base directory เว้นว่าง, Build command เว้นว่าง, Publish directory = `docs` (อ่านจาก netlify.toml ให้อัตโนมัติ) → **Deploy**
4. **Site configuration → Change site name** เช่น `pakkred-supply` → เว็บจะอยู่ที่ `https://pakkred-supply.netlify.app`
5. ทุกครั้งที่ push เข้า branch นั้น Netlify จะอัปเดตเว็บให้เอง (ประมาณ 1 นาที)

- Netlify ดึงโค้ดจาก repo แบบ **private** ได้ (GitHub Pages แบบฟรีทำไม่ได้) ถ้าเปลี่ยน repo เป็น private ให้ปิด GitHub Pages ด้วย
  และคัดลอก `AllInOne.gs` จากหน้าไฟล์บน GitHub (กด Raw ขณะล็อกอิน) แทนลิงก์ raw สาธารณะ
- ใช้ Netlify แล้วไม่ต้องใช้ GitHub Pages (ปิดได้ที่ Settings → Pages) จะได้มีเว็บเดียว

### ทางเลือก: เผยแพร่ด้วย Cloudflare (ฟรี)
repo มี [`wrangler.jsonc`](wrangler.jsonc) (เผยแพร่โฟลเดอร์ `docs/` แบบไฟล์ล้วน) และ [`scripts/cf-headers.js`](scripts/cf-headers.js)
ซึ่งสร้างส่วนหัวความปลอดภัย/แคช (`docs/_headers`) จาก `netlify.toml` ตอน deploy จึงตรงกับ Netlify เสมอ และไม่ชนกันถ้ายังเปิด Netlify ไว้
1. เข้า https://dash.cloudflare.com → สมัคร/ล็อกอิน (แผน **Free**)
2. **Workers & Pages → Create application → Import a repository** (หรือ Continue with GitHub) → อนุญาตเข้าถึง repo `borrow` → เลือก repo
3. ตั้งค่า: Project name เช่น `pakkred-supply`
   - **Build command** = `node scripts/cf-headers.js`
   - **Deploy command** = `npx wrangler deploy` (ค่าเริ่มต้น)
   - Production branch = branch หลักของ repo → **Deploy**
4. เว็บจะอยู่ที่ `https://pakkred-supply.<ชื่อบัญชี>.workers.dev` (ใส่โดเมนเองได้ที่ Settings → Domains & Routes)
5. ทุกครั้งที่ push เข้า branch หลัก Cloudflare จะอัปเดตเว็บให้เอง

ถ้าหน้าจอเป็นแบบ **Pages** (Create → Pages → Connect to Git): Framework preset = None, **Build command** = `node scripts/cf-headers.js`, **Build output directory** = `docs`

- `API_URL` และ Apps Script ใช้ตัวเดิมได้เลย ไม่ต้องแก้หรือ Deploy ใหม่
- ย้ายเสร็จแล้วลบเว็บบน Netlify ได้ (Site configuration → Delete this site) แจ้งลิงก์ใหม่ให้ทุกแผนก และคนที่เพิ่มเว็บไว้หน้าจอโฮมให้เพิ่มใหม่

### ขั้นที่ 2: เชื่อม Google Sheets เพื่อให้ทุกเครื่องใช้ข้อมูลพัสดุ/สต็อกชุดเดียวกัน (ประมาณ 10 นาที)

**Google Sheet มาจากไหน?** สร้างใหม่เองด้วยบัญชี Google (Gmail หรือบัญชี Google Workspace ของโรงพยาบาล) ไม่ต้องมีชีตเดิม
ชีตเปล่า 1 ไฟล์พอ ระบบจะสร้างแท็บและใส่ข้อมูลพัสดุ/แผนกให้เองในข้อ 6
ชีตเป็นของบัญชีที่สร้าง และเว็บจะบันทึกข้อมูลในนามบัญชีนั้น จึงแนะนำให้ใช้บัญชีกลางของงานพัสดุแทนบัญชีส่วนตัว
และไม่ต้องแชร์ชีตให้ผู้ใช้คนอื่น ทุกคนใช้งานผ่านเว็บได้เลย

ทำบนคอมพิวเตอร์ (หน้า Apps Script ใช้บนมือถือไม่สะดวก)
1. เข้าสู่ระบบบัญชี Google แล้วเปิด https://sheets.new (หรือ Google Drive → ใหม่ → Google ชีต) แล้วตั้งชื่อ เช่น "ระบบเบิก-ยืมพัสดุ"
2. ในชีต ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. เปิดไฟล์ [`docs/apps-script/AllInOne.gs`](docs/apps-script/AllInOne.gs) บน GitHub แล้วกดปุ่ม **Raw** (หน้าข้อความล้วน)
   กด **Ctrl+A** แล้ว **Ctrl+C** เพื่อคัดลอกทั้งไฟล์ (ไฟล์นี้รวม Code + Core + SeedData ไว้แล้ว)
   > อย่าคัดลอกจากหน้า Pull Request / "Files changed" เพราะจะมีเครื่องหมาย `+` ติดมาทุกบรรทัด
4. กลับมาที่ Apps Script ให้เหลือไฟล์ `Code.gs` ไฟล์เดียว (ถ้าเคยสร้าง `Core` / `SeedData` ไว้ ให้ลบทิ้ง)
   ลบโค้ดเดิมใน `Code.gs` ทั้งหมด แล้ววาง (Ctrl+V) จากนั้นแก้บรรทัด `var ADMIN_PIN = '1234';` เป็น PIN ของคุณเอง
5. กด **บันทึก** (รูปแผ่นดิสก์ หรือ Ctrl+S) ต้องบันทึกผ่านโดยไม่มีแถบสีแดง
   > ถ้าขึ้น *"พยายามใช้ setup แล้ว แต่บันทึกไม่ได้"* แปลว่าโค้ดที่วางไม่ครบหรือมีอักขระเกินมา
   > ให้ลบเนื้อหาใน `Code.gs` ทั้งหมดแล้วคัดลอกจากหน้า Raw ใหม่อีกครั้ง
6. เลือกฟังก์ชัน **`setup`** ในแถบด้านบน แล้วกด **เรียกใช้ (Run)**
   ครั้งแรก Google จะขอสิทธิ์ ให้กด ตรวจสอบสิทธิ์ → เลือกบัญชี → ขั้นสูง (Advanced) → ไปที่โปรเจกต์ (ไม่ปลอดภัย) → อนุญาต (Allow)
   จากนั้นในชีตจะมีแท็บ อุปกรณ์ (= รายการพัสดุ) / ประวัติการเบิก (= ใบเบิกทุกใบ) / หน่วยงาน (= แผนก) ฯลฯ พร้อมข้อมูลจาก SeedData
   > รัน `setup` ซ้ำได้จนกว่าจะเริ่มมีการเบิก/ยืมจริง (จะเขียนทับรายการพัสดุ แผนก และประวัติสต็อกด้วยข้อมูลใน SeedData)
   > หลังเริ่มใช้งานแล้ว ระบบจะไม่ยอมเขียนทับ เพื่อป้องกันข้อมูลหาย
7. กด **ทำให้ใช้งานได้ (Deploy) → การทำให้ใช้งานได้รายการใหม่ (New deployment)** → ไอคอนเฟือง เลือก **เว็บแอป (Web app)**
   - ดำเนินการในฐานะ (Execute as): **ฉัน (Me)**
   - ผู้มีสิทธิ์เข้าถึง (Who has access): **ทุกคน (Anyone)**
   - กด Deploy แล้วคัดลอก **URL ของเว็บแอป** (ลงท้ายด้วย `/exec`)
8. กลับมาที่ GitHub เปิดไฟล์ [`docs/config.js`](docs/config.js) กดรูปดินสอ (Edit) แล้ววาง URL ลงใน `API_URL: '...'`
   และแก้ `HOSPITAL_NAME` เป็นชื่อหน่วยงานของคุณ (แสดงบนหัวกระดาษ PDF) จากนั้นกด **Commit changes** แล้วรอ 1–2 นาที

> **เคยติดตั้งไว้แล้ว?** วาง `AllInOne.gs` ใหม่ทับใน `Code.gs` (ข้อ 3–5) แล้วรัน `setup` อีกครั้ง
> ถ้ายังไม่มีการเบิก/ยืม (ถ้ามีแล้ว ให้ลบแท็บ "ประวัติการเบิก" ก่อน) จากนั้นไปที่
> **Deploy → Manage deployments → แก้ไข (ดินสอ) → Version: New version** แล้วกด Deploy ข้อมูลเดิมยังใช้ได้
> (ระบบจะเพิ่มคอลัมน์ `kind` ในแท็บอุปกรณ์ และ `type` ในแท็บประวัติการเบิกให้เอง พัสดุเดิมจะตั้งเป็น "เบิกและยืมได้")

### ใช้งานบนมือถือและ iPad
- เปิดลิงก์เว็บใน Safari (iPhone/iPad) หรือ Chrome (Android) หน้าจอปรับตามขนาดเครื่องอัตโนมัติ ทั้งแนวตั้งและแนวนอน
- **เพิ่มเป็นไอคอนบนหน้าจอโฮม** ให้เปิดเต็มจอเหมือนแอป
  - iPhone / iPad: Safari → ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**
  - Android: Chrome → เมนู ⋮ → **เพิ่มลงในหน้าจอหลัก** (หรือ ติดตั้งแอป)
- **บันทึกใบเบิก/ใบยืม (PDF)** บน iPhone / iPad: แตะ "บันทึก PDF" แล้วเลือก **บันทึกไปยังไฟล์** (เก็บในแอปไฟล์) หรือ **พิมพ์** / AirDrop
  บน Android ไฟล์จะอยู่ในโฟลเดอร์ดาวน์โหลด
- รองรับ iOS / iPadOS 15.4 ขึ้นไป และ Android ที่ใช้ Chrome รุ่นปัจจุบัน

### ใส่สต็อกชุดใหม่ทั้งหมดจากไฟล์ (แทนที่ของเดิม)
รายการพัสดุและยอดคงเหลือใน `docs/seed-data.js` ตอนนี้เป็นไปตาม**ไฟล์ Stock วันที่ 21 ตุลาคม 2569** (301 รายการ รหัส NSO-001 ถึง NSO-301 เรียงตามไฟล์)
ใน Apps Script (วาง `AllInOne.gs` ล่าสุดแล้ว) เลือกฟังก์ชัน **`loadNewStock`** แล้วกด **เรียกใช้** 1 ครั้ง
ระบบจะลบรายการพัสดุเดิม ใบเบิก/ใบยืม และประวัติสต็อกทั้งหมด แล้วใส่รายการและยอดตามไฟล์ (บันทึกเป็นรับเข้า "ยอดยกมาเริ่มต้น")
รายชื่อแผนกอยู่ครบ · ย้อนกลับได้ที่ Google Sheet → ไฟล์ → ประวัติเวอร์ชัน

### เริ่มใช้งานจริง: ล้างข้อมูลทดลอง
ใน Apps Script เลือกฟังก์ชัน **`resetForLaunch`** ที่แถบด้านบน แล้วกด **เรียกใช้** 1 ครั้ง
ระบบจะลบใบเบิก/ใบยืม รายการในคำขอ และประวัติสต็อกทั้งหมด แล้วตั้งยอดคงเหลือทุกรายการเป็น 0
(รายชื่อพัสดุ รายชื่อแผนก และหมวดหมู่อยู่ครบ · เลขที่เอกสารเริ่มใหม่ที่ WD..-001)
จากนั้นใส่ยอดจริงในคอลัมน์ `available_qty` ของแท็บอุปกรณ์ หรือใช้ปุ่ม รับเข้า / ตรวจนับ บนเว็บ
ถ้ารันผิด ย้อนกลับได้ที่ Google Sheet → **ไฟล์ → ประวัติเวอร์ชัน**

### จัดการรายชื่อพัสดุใน Google Sheet
เจ้าหน้าที่เปิดชีตได้จากเว็บ: กดปุ่ม **เจ้าหน้าที่** ใส่ PIN แล้วไปที่เมนู **Google Sheet** (ลิงก์ส่งมาจาก Apps Script เฉพาะคนที่ใส่ PIN ถูก
ต้องวาง `AllInOne.gs` เวอร์ชันล่าสุดและ Deploy → New version ก่อน หรือใส่ `SHEET_URL` ใน `config.js` เอง) ชีตยังเปิดได้เฉพาะบัญชี Google ที่ได้รับสิทธิ์ตามปุ่มแชร์ของชีต

| แท็บ | ใช้ทำอะไร |
|---|---|
| **อุปกรณ์** | รายการพัสดุ: `code` รหัส, `name` ชื่อ, `category` หมวดหมู่, `unit` หน่วยนับ, `available_qty` คงเหลือ, `min_qty` จุดเตือนใกล้หมด, `location` ที่เก็บ, `active` (1 = เปิด, 0 = ปิด), `kind` ประเภทการใช้งาน |
| **หน่วยงาน** | รายชื่อ **แผนก** ที่แสดงให้เลือกในฟอร์ม: `name` ชื่อย่อ (เช่น ICU), `full_name` ชื่อเต็ม (แสดงในใบเบิก/ใบยืม) |
| **ประวัติการเบิก** (เดิมชื่อ คำขอยืม เปลี่ยนชื่อให้อัตโนมัติ) | 1 แถวต่อใบเบิก ล่าสุดอยู่บน: เลขที่ วันที่ ประเภท ผู้เบิก แผนก **รายการพัสดุ** จำนวนรวม สถานะ หมายเหตุ · คอลัมน์หัว**สีเทา**ท้ายตารางเป็นข้อมูลระบบ (ห้ามแก้) |
| **รายการในคำขอ** | ข้อมูลระบบ: พัสดุแต่ละชิ้นในใบเบิก/ใบยืม |
| **ประวัติสต็อก** | ทุกการเคลื่อนไหวของสต็อก ตรวจสอบย้อนหลังได้ |
| **รายการเบิก-ยืม** (แท็บแรก) | 1 แถวต่อพัสดุ 1 รายการ: วันที่, เลขที่, เบิก/ยืม, ผู้ขอ, แผนก, **ชื่อพัสดุ, จำนวน, หน่วย**, สถานะ, กำหนดคืน, คืนแล้ว, ยังไม่คืน (ล่าสุดอยู่บน ใช้ตัวกรอง/Pivot ได้) — ระบบสร้างใหม่ทุกครั้ง |
| **พัสดุที่ถูกยืมอยู่** | ใครยืมอะไรไป จำนวนที่ยังไม่คืน และกำหนดคืน (เรียงตามวันคืน) — ระบบสร้างใหม่ทุกครั้ง ไว้ดูอย่างเดียว |

คอลัมน์ที่หัวเป็น**สีฟ้าอ่อน** (เช่น ประเภท, สถานะ, รายการพัสดุ, ชื่อพัสดุ, ค้างคืน, ถูกยืมอยู่, เบิกไปแล้วรวม) ระบบเขียนให้อัตโนมัติเพื่อให้อ่านง่าย
แก้ในคอลัมน์เหล่านี้ไม่มีผล (จะถูกเขียนทับครั้งถัดไป)

ค่าในคอลัมน์ `kind`: `withdraw` = เบิกได้อย่างเดียว, `borrow` = ยืมได้อย่างเดียว, `both` = เบิกและยืมได้ (ข้อมูลตั้งต้นทุกรายการเป็น `both`)

ข้อมูลตั้งต้นใน `docs/seed-data.js`
- **คงเหลือ** = คอลัมน์ "คงเหลือ" ของ stock NSO ณ วันที่ 8 เมษายน 2569 (ช่องว่าง = 0)
- **จุดเตือนใกล้หมด** (`min_qty`) = ปริมาณจ่าย 6 เดือน ÷ 6 คือเตือนเมื่อเหลือไม่พอใช้ประมาณ 1 เดือน
- **หน่วยนับ** เดาจากชื่อพัสดุ (กล่อง/โหล/ม้วน/ฯลฯ ไม่พบ = ชิ้น) ตรวจและแก้ในแท็บอุปกรณ์ได้

**แก้ยอดคงเหลือในชีตโดยตรงได้** — แก้คอลัมน์ `available_qty` (คงเหลือ) คอลัมน์เดียว ไม่ต้องแตะ `total_qty` (ระบบคำนวณให้เองจาก คงเหลือ + ที่ถูกยืมออกไป)
เว็บจะเห็นยอดใหม่เมื่อเปลี่ยนหน้า กดรีเฟรช หรือสลับกลับมาที่แท็บ/แอป
- การแก้ในชีตโดยตรง **ไม่ถูกบันทึกในประวัติสต็อก** ถ้าต้องการประวัติครบ ให้ใช้ปุ่ม รับเข้า / ตรวจนับ ในโหมดเจ้าหน้าที่บนเว็บ
- แก้ชื่อ หน่วย ที่เก็บ `kind` และรายชื่อแผนกในชีตได้เลย
- **เพิ่มพัสดุใหม่ในชีตได้**: พิมพ์แถวใหม่ท้ายแท็บอุปกรณ์ ใส่ `code` (ไม่ซ้ำ), `name`, `unit`, `available_qty` (และ `category`, `min_qty`, `location` ถ้ามี)
  เว้น `id` และ `active` ว่างไว้ได้ ระบบตั้ง `id` ถัดไปให้และถือว่าเปิดใช้งาน (`unit` ว่าง = ชิ้น) · หรือเพิ่มผ่านเว็บ: เจ้าหน้าที่ → พัสดุคงเหลือ → + เพิ่มพัสดุ
- ถ้าแก้ในชีตตรงจังหวะที่มีคนกดบันทึกบนเว็บพอดี ค่าที่แก้อาจถูกเขียนทับ ให้ตรวจยอดอีกครั้งหลังแก้

### สต็อกเปลี่ยนอย่างไร

**เบิกของที่หมดได้** — ยอดคงเหลือจะ**ติดลบ** (เช่น -5 = ค้างจ่าย 5) เมื่อ **รับเข้า** ครั้งถัดไป ยอดที่รับเข้าจะหักล้างยอดติดลบก่อนโดยอัตโนมัติ (เช่น -5 รับเข้า 20 → เหลือ 15)
| การทำรายการ | คงเหลือ (`available_qty`) | จำนวนทั้งหมด (`total_qty`) |
|---|---|---|
| เบิก | ลดลงทันที | ลดลง (ของออกจากคลังถาวร) |
| ยืม | ลดลงทันที | เท่าเดิม |
| **ถึงวันคืน (อัตโนมัติ)** | เพิ่มกลับเท่าที่ยังค้าง | เท่าเดิม |
| รับคืน (เจ้าหน้าที่ กดก่อนถึงวันคืนได้) | เพิ่มกลับ | เท่าเดิม |
| แจ้งชำรุด/สูญหายตอนคืน | — | ลดลง |

**คืนเข้าสต็อกอัตโนมัติเมื่อถึงวันคืน** — ตั้งแต่ 00:00 ของวันคืน ระบบจะคืนจำนวนที่ยังค้างของใบยืมเข้า "คงเหลือ"
และปิดใบยืมเป็น "คืนอัตโนมัติ" **โดยไม่สนว่าของคืนจริงแล้วหรือยัง** (บันทึกในประวัติสต็อกว่า "คืนอัตโนมัติเมื่อถึงวันคืน")
- ทำงานจาก trigger รายวันของ Apps Script (ประมาณ 00:00–01:00) และตรวจซ้ำทุกครั้งที่มีคนเปิดเว็บ
- จึงเลือกวันคืนได้ตั้งแต่ **วันพรุ่งนี้** เป็นต้นไป
- ถ้าคืนก่อนกำหนด เจ้าหน้าที่กด "บันทึกรับคืน" ได้ตามเดิม ถ้าถึงวันคืนแล้วของไม่กลับมาจริง ใช้ "ตัดชำรุด" ในหน้าพัสดุ
- ต้องตั้งเขตเวลาเป็นไทย: Apps Script → **การตั้งค่าโปรเจกต์ (รูปเฟือง) → เขตเวลา = (GMT+07:00) Bangkok**
  และใน Google Sheet → **ไฟล์ → การตั้งค่า → เขตเวลา = (GMT+07:00) Bangkok**
- ติดตั้งไว้ก่อนมีฟีเจอร์นี้? วาง `AllInOne.gs` ใหม่ แล้วเลือกฟังก์ชัน **`installDailyTrigger`** กด **เรียกใช้** 1 ครั้ง (อนุญาตสิทธิ์เพิ่ม) แล้ว Deploy เวอร์ชันใหม่

เลขที่เอกสาร: `WD69-001` (ใบเบิก) / `BR69-001` (ใบยืม) = ปี พ.ศ. 2 หลัก + ลำดับในปีนั้น (เริ่ม 001 ใหม่ทุกปี เกิน 999 เป็น 4 หลัก)

## แบบเซิร์ฟเวอร์ (Node.js)

เว็บแอปสำหรับให้หน่วยงานภายในโรงพยาบาลยืม-คืนครุภัณฑ์/อุปกรณ์การแพทย์จากคลังกลาง
โดย **ยอดสต็อกคงเหลือเชื่อมกับการยืม-คืนแบบอัตโนมัติ** และบันทึกประวัติการเคลื่อนไหวทุกครั้ง

## ความสามารถหลัก

| เมนู | รายละเอียด |
|---|---|
| **ภาพรวม** | จำนวนอุปกรณ์ทั้งหมด / คงเหลือพร้อมให้ยืม / กำลังถูกยืม / รออนุมัติ / เกินกำหนดคืน, รายการสต็อกต่ำกว่าจุดขั้นต่ำ, ความเคลื่อนไหวล่าสุด |
| **คลังอุปกรณ์** | ค้นหา กรองตามหมวด ดูยอด *คงเหลือ / ทั้งหมด / ถูกยืม* แบบเรียลไทม์, ดูว่าใครยืมอยู่, ประวัติสต็อกรายชิ้น, รับเข้า, ตรวจนับปรับยอด, ตัดชำรุด/สูญหาย, นำเข้า/ส่งออก CSV |
| **ยืมอุปกรณ์** | เลือกหลายรายการในคำขอเดียว ระบบตรวจว่าไม่เกินยอดคงเหลือ, เจ้าหน้าที่คลังเลือก "จ่ายทันที" ได้ |
| **รายการยืม-คืน** | สถานะ รออนุมัติ → กำลังยืม → คืนแล้ว (หรือ ไม่อนุมัติ/ยกเลิก), แจ้งเกินกำหนดคืน, คืนบางส่วนได้, บันทึกชำรุด/สูญหายตอนคืน, พิมพ์ใบยืม, ส่งออก CSV |
| **ประวัติสต็อก** | Log ทุกการเคลื่อนไหว (รับเข้า / ยืมออก / รับคืน / ปรับปรุงยอด / ชำรุด-สูญหาย) พร้อมยอดคงเหลือหลังทำรายการ กรองตามช่วงวันที่ ส่งออก CSV |
| **ข้อมูลพื้นฐาน** | จัดการหน่วยงาน/แผนก, หมวดหมู่อุปกรณ์, ผู้ใช้งานและสิทธิ์ |

### สิทธิ์ผู้ใช้
- **เจ้าหน้าที่คลัง (admin)** – อนุมัติ/จ่าย, รับคืน, จัดการสต็อกและข้อมูลพื้นฐานทั้งหมด
- **ผู้ใช้หน่วยงาน (staff)** – ดูสต็อกคงเหลือ, ส่งคำขอยืม, ดู/ยกเลิกคำขอของหน่วยงานตนเอง

### สต็อกเชื่อมกับการยืม-คืนอย่างไร
- `จำนวนทั้งหมด` = ที่โรงพยาบาลมีอยู่, `คงเหลือ` = อยู่ในคลังพร้อมให้ยืม, `ถูกยืม` = ทั้งหมด − คงเหลือ
- ส่งคำขอ → ยังไม่ตัดสต็อก (แต่ตรวจว่าของพอ)
- อนุมัติ/จ่าย → `คงเหลือ` ลดลง (ตรวจซ้ำใน transaction ป้องกันจ่ายเกิน)
- รับคืน → `คงเหลือ` เพิ่มกลับ / แจ้งชำรุด-สูญหาย → `จำนวนทั้งหมด` ลดลง
- ทุกครั้งบันทึกลง `stock_movements` ตรวจสอบย้อนหลังได้

บัญชีทดลอง (สร้างอัตโนมัติครั้งแรก พร้อมข้อมูลตัวอย่าง — **ควรเปลี่ยนรหัสผ่านทันที**)

|---|---|---|
| `admin` | `admin1234` | เจ้าหน้าที่คลัง |
| `ward` | `ward1234` | ผู้ใช้หน่วยงาน (หอผู้ป่วยอายุรกรรมชาย) |

### ตัวแปรสภาพแวดล้อม

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|

| `APP_SECRET` | สุ่มทุกครั้งที่เริ่ม | คีย์สำหรับ token เข้าสู่ระบบ ควรตั้งค่าเพื่อไม่ให้ผู้ใช้หลุดเมื่อรีสตาร์ท |

## การเชื่อมข้อมูลกับระบบอื่น

1. **นำเข้า CSV** (เมนูคลังอุปกรณ์ → นำเข้า CSV) – ใช้ดึงยอดจากระบบคลังเดิม/Excel
   คอลัมน์: `รหัส, ชื่อ, หมวดหมู่, หน่วย, จำนวนทั้งหมด, จุดสั่งซื้อขั้นต่ำ, สถานที่เก็บ`
   รหัสเดิมจะถูกอัปเดตยอด (บันทึกเป็นการปรับปรุงยอด), รหัสใหม่จะถูกเพิ่ม
2. **ส่งออก CSV** – สต็อกคงเหลือ, รายการยืม-คืน, ประวัติสต็อก (เปิดใน Excel ภาษาไทยได้)
3. **REST API อ่านยอดคงเหลือ** – ตั้ง `STOCK_API_KEY` แล้วเรียก
   ```bash
   curl -H "X-API-Key: <key>" http://localhost:3000/api/public/stock
   ```
4. ทุกหน้าจอใช้ JSON API ภายใต้ `/api/*` (ส่ง header `Authorization: Bearer <token>` ที่ได้จาก `POST /api/login`) สามารถนำไปเชื่อมกับระบบอื่นได้
